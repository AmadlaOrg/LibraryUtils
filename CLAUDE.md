## Project Overview

LibraryUtils is a Go utility library providing shared functionality across Amadla projects. It includes utility functions, services (git, database, file operations), and mockable interfaces for common Go and external libraries.

## Build and Development Commands

```bash
make install-deps    # Install dev tools (golangci-lint, mockery, coverage tools)
make generate        # Generate mock code via mockery
make test            # Run all tests including integration tests
make lint            # Run golangci-lint
make lint-fix        # Run golangci-lint with auto-fix
make test-cov        # Run tests and open coverage report
make clean           # Remove bin and coverage files
```

**Running a single test:**
```bash
go test -v -run TestFunctionName ./path/to/package/...
```

**Running integration tests only:**
```bash
go test -tags=integration ./...
```

## Architecture

### Package Structure
- `configuration/` - Config management via Viper
- `database/sqlite3/` - SQLite3 with interface wrappers for all sql types
- `database/ristretto/` - In-memory caching
- `encryption/aes_gcm/` - AES-GCM encryption service
- `file/` - File system operations
- `git/` - Git operations via go-git (includes `remote/` and `config/` subpackages)
- `interconnection/` - IPC with platform-specific implementations:
  - `client/` and `server/` with `unix/socket/`, `unix/dbus/`, `windows/named_pipe/`
- `location/` - XDG path utilities
- `packaging/desktop/`, `packaging/document/` - Package generation

### Naming Conventions
- **Interfaces:** Named after their purpose, no prefix (e.g., `File`, `Git`, `Database`)
- **Structs:** Unexported implementation types (e.g., `gitImpl`, `databaseImpl`)
- **Constructors:** `New()` when one per package, returning the interface type
- **Mocks:** `Mock*` (generated by mockery)

### Service Pattern
Each service follows this structure:
```go
type Git interface { /* methods */ }
type gitImpl struct { /* fields */ }
func New(url, repoPath string, cnf *config.Config) Git {
    return &gitImpl{...}
}
```

### Dependency Injection for Testing
OS/system calls are assigned to package-level function variables, enabling test mocking:
```go
var osOpen = os.Open  // Can be replaced in tests
```

## Testing

- Unit tests: `*_test.go`
- Integration tests: `*_integration_test.go` (require `-tags=integration`)
- Uses `testify/assert` and `testify/mock`
- Table-driven tests are the standard pattern
- Coverage excludes mocks and generated files (see `.covignore`)

## Mock Generation

Mocks are configured in `.mockery.yaml`. After modifying interfaces:
```bash
make generate
```

Mocks are generated in-package alongside their interfaces.
